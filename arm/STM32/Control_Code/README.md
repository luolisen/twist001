# X42S CAN 只读台架固件 v1

本目录是从旧 Control_Code 提取的独立工程。Mac 是源码主副本，Windows 只接收冻结包并用 Keil Community / ARM Compiler 6.24 编译。旧工程保持原样。

## 使用范围

仅 STM32F407VGT6、CAN2 和 USART1。移除 SMD 私有协议、K230、气泵、OLED、旧运动流程和上电自动捕获零点。没有使能、位置控制、回零或夹爪动作命令。上电不主动发查询，模型状态始终 UNHOMED。

CAN2：PB12 RX、PB13 TX；使用 SN65HVD230 的 RXD/TXD 对应接线，3.3V 与共地。总线两端终端电阻、电机供电及收发器模块具体引脚须现场核对。USART1：PA9 TX、PA10 RX，USB-TTL 为 3.3V 电平，115200 / 8N1。代码沿用原工程 HSI→168MHz、APB1=42MHz，CAN 6×(1+10+3)=84，因此 500kbit/s。

## 串口命令

每条命令以 LF 或 CRLF 结尾，大写，上一条输出完成后再发下一条；这是台架诊断协议，不是模型 25Hz 控制协议。

- `ID?` / `HELP`：固件身份及帮助，不发 CAN。
- `READ 1` 到 `READ 6`：查询单轴位置。
- `SCAN`：顺序查询六轴，结束输出 SCAN_DONE。
- `STATE`：打印缓存，有效性与反馈年龄，不发 CAN。
- `LISTEN`：接收最多1秒或100帧，不发应用 CAN 请求。正常 CAN 模式仍会 ACK；不等同于电气静默模式。

查询使用扩展 ID `address << 8`，DLC=2，数据 `36 6B`。有效位置回包须是同一扩展 ID、数据帧、DLC=7、`36 sign magnitude_be32 6B`；sign只接受0/1，量纲为0.1电机轴度。尾字节6B是协议结束标记，不能称为CRC。支持完整32位无符号幅值，避免负数/大值解析溢出。

输出保留 TX/RX 原始帧、时间戳、电机轴度、valid/fresh、CAN错误码及ESR。TX只代表提交发送邮箱，不代表电机收到。每次查询前清旧队列，发送等待最多50ms、回包等待250ms；超时清本次valid，发送邮箱超时中止。禁止无限自动重发。协议本身没有事务序号，极端迟到的同轴回包仍可能无法区分，后续动作控制前需继续设计。

`motor_deg` 是电机轴反馈；未做减速比、方向和机械参考标定，不能当作模型关节角。未回包的数据不得用0或目标位置冒充有效状态。

## 后续模型 / ESP32 边界

1. `x42s_protocol`：无HAL依赖，只构造位置读取、验证原始回包；主机测试与STM32共用。
2. `readcan_app`：HAL传输、串口诊断、六轴反馈记录；原始值与接收时间同处一条记录。
3. 后续新增 `joint_calibration`：用实测方向、减速比、参考姿态/临时零偏换算为关节rad，显式人工对齐确认后才能放行。断电、掉线或故障清除归零状态。
4. 后续新增 `host_protocol`：对齐现有模型 `state/action` 七维，前六维关节输出端rad、第七维逻辑夹爪0..1；版本、序号、CRC和反馈时效独立检查。模型25Hz控制与目前诊断命令不混用。
5. 后续新增 `esp32_link`：独立串口模块负责夹爪命令、实际状态回读及超时；逻辑开度经实测毫米标定映射。ESP32现有ASCII固件与拟议新协议分别适配，不把目标回显当测量值。串口与引脚待核实，当前不初始化USART3/UART4。

## 验证

Mac：协议测试及HAL模拟测试，用 -Wall -Wextra -Werror、地址/未定义行为检查运行；覆盖六轴ID、正负/32位幅值、错误ID/帧型/长度/功能码/尾字节、禁止运动命令、超时中止及反馈失效。

Windows：打开 MDK-ARM/readcan.uvprojx，F7编译。传输脚本逐文件校验SHA256，只构建和打开工程，不调用烧录。CubeMX重新生成会覆盖定制文件，当前不可直接用原test.ioc重生成。

待硬件验收：接线、上电串口BOOT、单轴READ、PCAN原始帧对照、六轴SCAN与拔线超时。当前尚未烧录，没有STM32实物CAN通信证据。

协议依据：现有项目 integration/X42S_STM32_ESP32_归零与策略接口草案.md 和 Joint_J1_J5_Test/Test-J1-to-J5.ps1 中既有PCAN位置读取实现；本次只实现已记录的0x36，不扩展未知功能码。
